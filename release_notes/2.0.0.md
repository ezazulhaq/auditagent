# AuditAgent v2.0.0 Release Notes

**Release Date:** September 30, 2026

We are excited to announce AuditAgent 2.0.0! This major release brings a significant architectural overhaul to our data and persistence layers, ensuring better scalability and concurrent stability for production environments.

## 🚀 Major Features & Breaking Changes

### PostgreSQL Migration for Transactional Persistence
AuditAgent has migrated its primary transactional database from DuckDB to PostgreSQL. 
* **Why:** As AuditAgent's usage scales, concurrent read/write operations and schema requirements (like secondary indexes) outgrew DuckDB's single-file architecture and update limitations.
* **What changed:** All core transactional data—including scan reports, vulnerabilities, user sessions, GitHub authorizations, agent runs, checkpoints, and durable LangGraph4j state—now securely persists in PostgreSQL.

### DuckDB Repurposed strictly for Knowledge Base (FTS)
DuckDB hasn't been completely removed; it has been highly specialized. 
* DuckDB is now **strictly limited to the Full-Text Search (FTS) knowledge base**.
* It continues to power the BM25 lexical ranking algorithm to instantly inject relevant repository memories (both successful remediations and rejected failures) into the AI agent's context.

## 🛠 Configuration & Operations

This architectural change requires updates to your deployment environment variables and application configurations:

* **New PostgreSQL Requirements:**
  You must now provision a PostgreSQL instance and provide the following environment variables:
  * `SPRING_DATASOURCE_URL` (e.g., `jdbc:postgresql://postgres-host:5432/auditagent`)
  * `SPRING_DATASOURCE_USERNAME`
  * `SPRING_DATASOURCE_PASSWORD`

* **DuckDB Configuration:**
  The existing `AUDITAGENT_DB_PATH` environment variable is retained, but it now strictly points to the DuckDB FTS file rather than the primary database. 

## 📚 Documentation Updates
The entire documentation suite (`doc/`) has been rewritten to reflect the new dual-database architecture. 
* Updated `08-data-and-persistence.md` outlining the precise boundary between PostgreSQL (Source of Truth) and DuckDB (FTS).
* Updated `11-setup-configuration-operations.md` with new deployment requirements and secure backup routines.
* Updated the Security Model (`10-security-model.md`) and Feature Catalog (`03-feature-catalog.md`).

## 🐞 Bug Fixes
* **JPQL Null Checks:** Fixed critical JPQL regressions where null bounds (`:runId IS NULL`) were failing to retrieve message history.
* **Process Runner:** Resolved zombie process timeouts in the sandbox environment by safely bypassing inaccurate `isAlive()` assertions for orphaned children.
