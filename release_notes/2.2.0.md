# AuditAgent v2.2.0 Release Notes

**Release Date:** October 28, 2026

AuditAgent 2.2.0 introduces **GitHub Issue Webhook Support**, expanding the platform's automation capabilities beyond pull requests. Developers can now triage, analyze, and autonomously fix security vulnerabilities directly from GitHub Issues, closing the loop with automated pull requests and bi-directional status synchronization.

---

## 🚀 New Features & Enhancements

### 1. GitHub Issue Webhook Ingestion (`GitHubWebhookController`)
* Added support for `X-GitHub-Event: issues` payloads in `POST /api/webhooks/github` alongside existing `pull_request` events.
* Maintains strict HMAC-SHA256 signature verification (`X-Hub-Signature-256`) and idempotency deduplication (`X-GitHub-Delivery`).
* Dispatches issue lifecycle events (`opened`, `reopened`, `labeled`, and `closed`) to `IssueLifecycleService`.

### 2. Autonomous Issue Remediation & Lifecycle Management (`IssueLifecycleService`)
* **Trigger Filtering**: Evaluates issue events against configured security labels (`auditagent-fix`, `security`, `auditagent`) or mentions (`@auditagent`, `VULN-XXXXXX`) to prevent unintentional execution on non-security issues.
* **Two-Tier Vulnerability Resolution**:
  1. *Explicit Identifier*: Extracts `VULN-XXXXXX` from issue title or description for deterministic matching against repository findings.
  2. *Semantic LLM Triage*: When no explicit ID is provided, leverages the LLM to match the reported issue against active detected vulnerabilities on the default branch (`master` / `main`).
  3. *Diagnostic Fallback*: Posts a helpful comment on the issue if no active scan exists or if no matching vulnerability is detected, inviting the author to supply a finding ID or trigger a scan.
* **Autonomous Remediation**: Executes the LangGraph4j remediation graph (`ValidateAccessNode` → `CloneWorkspaceNode` → `agent_loop` → `ApprovalReadyNode` → `PublicationNode`) in an isolated virtual thread under actor identity `github-bot` on a dedicated thread (`issue-<repoId>-<issueNumber>`).
* **Issue Closure Handling**: When an issue is closed in GitHub without merging a PR, automatically discards active or interrupted runs for that issue thread to maintain clean lifecycle state.

### 3. Bi-Directional Issue Linking & Comments
* **Pull Request Linking**: Appends `Fixes #<issueNumber>` to the generated pull request description so that GitHub automatically links and closes the issue upon PR merge.
* **Issue Comments**: Adds `createIssueComment()` to `GitHubApiClient` using GitHub App installation credentials to post real-time updates and PR links with verification summaries (compile, unit tests, and security rescan results) directly on the issue thread.
