# AuditAgent v2.2.1 Release Notes

**Release Date:** October 29, 2026

AuditAgent 2.2.1 resolves an issue where analyzing security findings (both single-vulnerability analysis and batch remediation) did not record or track error and success notifications in the top-level notifications dropdown. It also resolves a backend persistence defect where notification read states were not preserved and cached entities were returned after mark-as-read operations.

---

## 🚀 Enhancements & Bug Fixes

### 1. Finding Analysis & Remediation Notification Tracking (`useRemediationController`)
* **Single Vulnerability Remediation**:
  * Dispatches `success` notifications when analysis completes and fix verification is confirmed (`analysis_complete` awaiting approval), and when automated pull requests are opened (`pr_created`).
  * Dispatches `error` notifications when analysis encounters failures via SSE status events (`Remediation failed`) or when network/runtime exceptions are thrown.
* **Batch Remediation Pipeline**:
  * Tracks individual successes and failures per analyzed vulnerability in real time.
  * Emits an aggregated completion summary notification upon batch completion (e.g. `Batch analysis completed: 2 of 2 vulnerabilities analyzed`).
* **Publication & Decision Tracking**:
  * Dispatches notifications for pull request publication successes, failures, and retry events.

### 2. Scan Lifecycle Notifications (`useScanController`)
* Dispatches `success` and `error` notifications upon completion or failure of both GitHub branch scans and ZIP archive upload scans.

### 3. Real-Time Notification Center UX (`NotificationDropdown`, `auditApi`)
* `auditApi.saveNotification` now dispatches the `notification-added` CustomEvent on `window` to notify client components immediately.
* `NotificationDropdown` optimistically incorporates incoming notifications for instant UI response before server synchronization.
* Added visual unread indicators (`cyan` dot), unread count badges in the header (`X new`), and safe date formatting fallbacks.

### 4. Backend Read-State Mapping & Entity Invalidation
* **`UserDataService.java`**: Fixed `mapToNotification` to map `isRead` from `UserNotification` to the `Notification` domain model.
* **`UserNotificationRepository.java`**: Added `@Modifying(clearAutomatically = true)` to `markAllAsReadByUserId` to invalidate first-level persistence cache and prevent stale read-state returns.
