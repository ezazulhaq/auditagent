# AuditAgent v2.4.1 Release Notes

**Release Date:** November 9, 2026

AuditAgent 2.4.1 enhances the **Token Usage Observability Module** by tracking, aggregating, and displaying LLM token consumption by **Repository Full Name** (`owner/repo`) rather than raw internal repository IDs (`repoPath` like `github:42:main`). This significantly improves observability, auditability, and team-level cost tracking across multi-repository environments.

---

## 🚀 New Features & Enhancements

### 1. Repository Name Observability Tracking
* **Repository Full Name Resolution**: When storing token metrics in `token_usage`, `ScanDataService` now resolves the target repository's full name (e.g., `owner/repo`) directly from `ManagedRepositoryRepository`.
* **Clean Fallback Strategy**: Safely maps general chat threads (`github:general:...`) to `"General Chat"` and file upload sessions (`upload:...`) to `"Project Upload"`, gracefully falling back to repository identifiers if repository metadata has not yet synced.
* **Aggregated Metric Reporting**: Updated `TokenUsageRepository.findTokenUsageSummaryByUserId` to aggregate consumption records across branches and runs by repository full name and model (`GROUP BY COALESCE(t.repoName, t.repoPath), t.modelName`).

### 2. Frontend Observability Dashboard
* **Human-Readable Repository View**: `TokenUsageLayout` now renders clean repository full names in the table and tooltip titles instead of obscure numeric IDs and branch paths.
* **Full Backward Compatibility**: The backend returns both `repoName` and `repoPath` populated with the repository name, ensuring legacy consumers and scripts continue to function without disruption.
