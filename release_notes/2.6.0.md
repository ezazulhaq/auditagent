# AuditAgent v2.6.0 Release Notes

**Release Date:** November 11, 2026

AuditAgent 2.6.0 introduces the **Comprehensive SOLID Architecture & Governance Framework**, modernizing both the React frontend and Java/Spring Boot backend to strictly adhere to SOLID object-oriented and component design principles. This release eliminates monolithic components and services, avoids brittle prop-drilling, establishes strategy registries for security scanners and document exporters, decomposes agent tools into segregated role interfaces, extracts conversational chat triage from LLM remediation loops, and enforces an automated workspace policy (`.agents/rules/solid-principles-policy.md`) requiring strict SOLID compliance across all future contributions.

---

## 🚀 New Features & Enhancements

### 1. Backend SOLID Modernization & Strategy Registries
* **Polymorphic Scanner Strategy (`OCP` & `DIP`)**:
  * Introduced `SecurityScanner` interface (`getScannerName`, `supports`, `scan`, `detectLanguages`, `detectLanguageForFile`, `getRuleConfigs`).
  * Created `ScannerRegistry` for dynamic scanner engine resolution by name (`semgrep`, etc.).
  * Updated `ScanOrchestratorService` and `ProjectUploadService` to inject `SecurityScanner` and `ScannerRegistry` rather than coupling to concrete CLI classes.
* **Reporting Strategy & Metrics Decomposition (`SRP` & `OCP`)**:
  * Created `ReportExporter` strategy interface with format-specific exporters: `MarkdownReportExporter`, `HtmlReportExporter`, and `PdfReportExporter`.
  * Extracted `SecurityMetricsCalculator` (SRP) to compute severity counts, risk posture heuristics, and compliance text independently of document formatting.
  * Refactored `ReporterService` into a clean facade implementing `ReportGenerator` (DIP).
* **Segregated Agent Tool Role Interfaces (`ISP` & `SRP`)**:
  * Decomposed 800-line monolithic `AgentToolService` into focused role interfaces in `com.cb.auditagent.service.tool`:
    * `WorkspaceInspector`: `readFile`, `searchCodebase`, `hashFile`
    * `WorkspacePatcher`: `applyPatch`, `rollbackFile`
    * `WorkspaceBuildVerifier`: `compileProject`, `runTests`, `runLinter`
    * `WorkspaceRescanner`: `rescanFile`, `runStaticAnalysis`
* **Chat Service & Token Accounting (`SRP` & `ISP`)**:
  * Extracted `ChatService` interface for user conversational assistance, vulnerability triage, and command dispatching (`[TRIGGER_SCAN]`, `[TRIGGER_FIX]`).
  * Extracted `LlmTokenTracker` for dedicated Micrometer metric recording and audit logging.
  * Refactored `AuditController` and `IssueLifecycleService` to depend on `ChatService` abstraction (DIP).
* **Dead Code Retirement**:
  * Safely removed obsolete `OrchestratorService.java` (622 lines of unused legacy DuckDB/thread coordination code).

### 2. Context-Driven Domain Architecture (Frontend DIP & ISP)
* **Granular Domain Providers**: Decomposed frontend application state into 5 specialized domain contexts in `frontend/src/context/`:
  * `ApiContext` (`useApi`): Inversion layer enabling clean dependency injection of API and SSE transports.
  * `AuthContext` (`useAuth`): Authenticated user session, CSRF tokens, login/logout, and LLM onboarding state.
  * `WorkspaceContext` (`useWorkspace`): GitHub repository discovery, branch selection, and audit scope configuration.
  * `ModalContext` (`useModals`): Centralized dialog, drawer, and confirmation modal state.
  * `AuditContext` (`useAudit`): Scan lifecycle, remediation workflows, finding inventory, and persistent memory.
* **Context Composition Root**: Assembled providers via `AppProviders.jsx` with strict dependency ordering.
* **Standardized Test Harness**: Introduced `renderWithProviders` in `frontend/src/test/test-utils.jsx` for isolated component testing.

### 3. Declarative Workspace & Modal Registries (Frontend OCP & SRP)
* **Lean App Shell**: Decomposed `App.jsx` from a 500-line monolithic god-component into a clean ~80-line composition shell.
* **Declarative Workspace Tabs**: Extracted tab definitions into `src/features/navigation/workspaceTabs.jsx` (`WORKSPACE_TABS`) dynamically consumed by `WorkspaceContainer.jsx`.
* **Centralized Modal Registry**: Built `src/components/ModalManager.jsx` consuming `ModalContext` to mount dialogs and drawers declaratively.

### 4. Monolithic Component Decomposition (Frontend SRP)
* **ScanPanel Decomposition**: Decomposed into `components/RepoBranchSelector.jsx`, `components/UploadDropzone.jsx`, and `components/ScanProgressTracker.jsx`.
* **FindingsView Decomposition**: Extracted `hooks/useFindingsFilter.js`, `constants/findingStyles.js`, `components/FindingsToolbar.jsx`, `components/FindingRow.jsx`, `components/FileGroup.jsx`, and `components/BulkActionBar.jsx`.
* **FindingDrawer Decomposition**: Extracted `constants/remediationConstants.js`, `components/RemediationTimeline.jsx`, `components/VulnerableCodeViewer.jsx`, `components/ApprovalPackageViewer.jsx`, and `components/RemediationDecisionBar.jsx`.
* **LlmConfigForm Decomposition**: Extracted `constants/llmProviders.js`, `hooks/useLlmConfigForm.js`, `components/ProviderSelector.jsx`, and `components/SystemOneSettings.jsx`.

### 5. Workspace Governance & Policy Enforcement
* **SOLID Principles Policy**: Added `.agents/rules/solid-principles-policy.md` defining non-negotiable rules for Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, and Dependency Inversion.
* **Pre-Flight Guardrail**: Updated `AGENTS.md` and repository guidelines mandating SOLID adherence for all future feature additions and refactoring.
