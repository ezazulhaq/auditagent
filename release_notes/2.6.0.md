# AuditAgent v2.6.0 Release Notes

**Release Date:** November 11, 2026

AuditAgent 2.6.0 introduces the **SOLID Frontend Architecture & Governance Framework**, overhauling the React frontend to strictly adhere to SOLID object-oriented and component design principles. This release eliminates monolithic components and brittle prop-drilling by establishing a granular Context-driven domain layer, declarative workspace tab and modal registries, dedicated presentation sub-components and custom hooks, and a standardized test harness. In addition, this release institutionalizes an automated workspace policy (`.agents/rules/solid-principles-policy.md`) requiring strict SOLID compliance across all future frontend and backend architectural additions.

---

## 🚀 New Features & Enhancements

### 1. Context-Driven Domain Architecture (DIP & ISP)
* **Granular Domain Providers**: Decomposed application state into 5 specialized domain contexts in `frontend/src/context/`:
  * `ApiContext` (`useApi`): Inversion layer enabling clean dependency injection of API and SSE transports.
  * `AuthContext` (`useAuth`): Authenticated user session, CSRF tokens, login/logout, and LLM onboarding state.
  * `WorkspaceContext` (`useWorkspace`): GitHub repository discovery, branch selection, and audit scope configuration.
  * `ModalContext` (`useModals`): Centralized dialog, drawer, and confirmation modal state.
  * `AuditContext` (`useAudit`): Scan lifecycle, remediation workflows, finding inventory, and persistent memory.
* **Context Composition Root**: Assembled providers via `AppProviders.jsx` with strict dependency ordering, preventing re-render storms while eliminating multi-level prop drilling.
* **Standardized Test Harness**: Introduced `renderWithProviders` in `frontend/src/test/test-utils.jsx` for testing components against isolated, mockable context providers.

### 2. Declarative Workspace & Modal Registries (OCP & SRP)
* **Lean App Shell**: Decomposed `App.jsx` from a 500-line monolithic god-component into a clean ~80-line composition shell.
* **Declarative Workspace Tabs**: Extracted tab definitions into `src/features/navigation/workspaceTabs.jsx` (`WORKSPACE_TABS`) dynamically consumed by `WorkspaceContainer.jsx`, enabling new tabs to be added without modifying core layout components.
* **Centralized Modal Registry**: Built `src/components/ModalManager.jsx` consuming `ModalContext` to mount modals, drawers, and confirmation dialogs declaratively.

### 3. Monolithic Component Decomposition (SRP)
* **ScanPanel Decomposition**: Decomposed into `components/RepoBranchSelector.jsx`, `components/UploadDropzone.jsx`, and `components/ScanProgressTracker.jsx`.
* **FindingsView Decomposition**: Extracted `hooks/useFindingsFilter.js`, `constants/findingStyles.js`, `components/FindingsToolbar.jsx`, `components/FindingRow.jsx`, `components/FileGroup.jsx`, and `components/BulkActionBar.jsx`.
* **FindingDrawer Decomposition**: Extracted `constants/remediationConstants.js`, `components/RemediationTimeline.jsx`, `components/VulnerableCodeViewer.jsx`, `components/ApprovalPackageViewer.jsx`, and `components/RemediationDecisionBar.jsx`.
* **LlmConfigForm Decomposition**: Extracted `constants/llmProviders.js`, `hooks/useLlmConfigForm.js`, `components/ProviderSelector.jsx`, and `components/SystemOneSettings.jsx`.

### 4. Workspace Governance & Policy Enforcement
* **SOLID Principles Policy**: Added `.agents/rules/solid-principles-policy.md` defining non-negotiable rules for Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, and Dependency Inversion.
* **Pre-Flight Guardrail**: Updated `AGENTS.md` and repository guidelines mandating SOLID adherence for all future feature additions and refactoring.
