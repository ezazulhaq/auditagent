# AuditAgent v2.11.0 Release Notes

**Release Date:** November 15, 2026

AuditAgent 2.11.0 delivers **Phase 4: Multi-Agent Star Topology & Supervisor Hardening**, transforming the multi-agent code remediation pipeline from fragile string-matched routing into a hardened, structured, and token-efficient orchestration architecture. This release introduces structured JSON output routing with Jackson schema validation (`SupervisorDecision`), resilient fuzzy enum normalization (`normalizeAgentEnum`), milestone-based context window compression (`StageMilestone`) that reduces supervisor prompt token growth from quadratic ($O(N^2)$) to linear ($O(N)$), and decoupled supervisor hop budgets (`max-supervisor-hops: 25`) from per-stage retry limits (`max-stage-retries: 3`), enabling autonomous 10+ stage remediation workflows without premature termination.

---

## 🚀 New Features & Enhancements

### 1. Structured JSON Output Routing (`SupervisorDecision`)
* **Typed Routing Contract**:
  * Introduced `SupervisorDecision(nextAgent, reasoning)` record supporting flexible JSON schema aliases (`next_agent`, `agent`, `nextStage`, `reason`, `rationale`, `thought`).
  * Enforces `ResponseFormat.JSON` via LangChain4j `ChatRequest`, ensuring the supervisor LLM responds with deterministic JSON objects rather than ambiguous freeform text.
  * Captures explicit routing `reasoning` and persists it directly into conversation memory and state (`supervisorReasoning`).
  * Gracefully falls back to unstructured chat requests if the underlying model/provider does not support native JSON mode.

### 2. Fuzzy Enum Normalization & Resilience (`normalizeAgentEnum`)
* **Markdown & Punctuation Stripping**:
  * Robustly strips surrounding code fences, markdown asterisks (`**STAGE**`), backticks (`` `STAGE` ``), quotes, colons, brackets, and trailing punctuation.
  * Standardizes case and converts hyphenated or space-separated variations (e.g., `root-cause`, `root cause` $\to$ `ROOT_CAUSE`; `data-flow` $\to$ `DATA_FLOW`; `post fix` $\to$ `POST_FIX`).
* **Text Fallback Token Extraction**:
  * Extracts target agent names from freeform sentences via regex word-boundary matching if model JSON parsing fails.
* **Strict Invariants**:
  * Strictly disallows re-routing to `PLANNING` once initial planning has generated a remediation plan.
  * Safely defaults unknown or unmapped stages to `FAIL`.

### 3. Milestone-Based Context Window Compression (`StageMilestone`)
* **Linear Context Growth ($O(N)$)**:
  * Replaced quadratic accumulation of full execution transcripts with compact `StageMilestone(stage, success, summary, touchedFiles)`.
  * Each worker stage execution is summarized and capped at 150 tokens (~600 chars), preventing quadratic prompt token inflation across multi-stage review workflows.
* **Automated Worker Graph Milestones**:
  * Updated `WorkerAgentGraphFactory` with a terminal `record_milestone` node, evaluating stage success, extracting touched files from AST trajectories, and writing compact summaries to state.
  * Updated `MultiAgentRemediationGraph` to accumulate milestones and track per-stage failure counts.

### 4. Decoupled Hop Limits & Retry Budgets
* **Decoupled Limits**:
  * Separated supervisor routing iterations from worker failure retries:
    * `auditagent.agent.max-supervisor-hops`: default `25` (configurable via `AUDITAGENT_AGENT_MAX_SUPERVISOR_HOPS` or `AUDITAGENT_SUPERVISOR_MAX_HOPS`).
    * `auditagent.agent.max-stage-retries`: default `3` (configurable via `AUDITAGENT_AGENT_MAX_STAGE_RETRIES` or `AUDITAGENT_STAGE_MAX_RETRIES`).
    * `auditagent.agent.structured-supervisor`: default `true` (configurable via `AUDITAGENT_AGENT_STRUCTURED_SUPERVISOR` or `AUDITAGENT_STRUCTURED_SUPERVISOR`).
  * Workflows can now smoothly navigate through all 12–16 review stages without hitting the former 5-iteration limit.
  * Aborts to `FAIL` only if a single worker stage fails repeatedly (3 times) or if total supervisor routing hops exceed 25.

### 5. Docker Compose & Environment Variable Spring Boot Compatibility
* **Relaxed Binding & Compose Modernization**:
  * Updated `.env.example`, `docker-compose.yml`, and `docker-compose-dev.yml` to provide bidirectional support for both canonical Spring Boot relaxed-binding environment variables (e.g. `AUDITAGENT_AGENT_MAX_SUPERVISOR_HOPS`, `AUDITAGENT_AGENT_MAX_STAGE_RETRIES`, `AUDITAGENT_AGENT_STRUCTURED_SUPERVISOR`, `AUDITAGENT_AGENT_MAX_ITERATIONS`, `AUDITAGENT_AGENT_BATCH_CONCURRENCY`, `AUDITAGENT_AGENT_SANDBOX_ENABLED`) and their short aliases.
  * Stripped obsolete legacy `SPRING_AI_*` variables from Docker compose files and synchronized RabbitMQ, PostgreSQL, Supabase, LLM, and scanner environment variables across production and development compose files.
