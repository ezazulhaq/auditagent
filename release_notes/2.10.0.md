# AuditAgent v2.10.0 Release Notes

**Release Date:** November 15, 2026

AuditAgent 2.10.0 delivers a major overhaul to the frontend **Notification Center & Operations Alerting Experience**, introducing a modernized header popover with live segmented filter tabs, smart deep linking into finding drawers and pull requests, granular read/unread management, inline confirmation for bulk clearing, and dedicated backend endpoints for individual read tracking and database notification purging.

---

## 🚀 New Features & Enhancements

### 1. Modernized Notification Center (`NotificationDropdown.jsx`)
* **Numeric Unread Counters**:
  * Replaced the ambiguous static red dot with a high-contrast pill counter (`99+`) displaying live unread counts directly over the header bell icon.
  * Added subtle pulse animations on the arrival of new unread items.
* **Explicit Read/Unread State Control**:
  * Preserves unread status when opening the dropdown so users don't lose track of unacknowledged alerts.
  * Added an explicit "Mark all read" button in the header with backend synchronization.
  * Single items are automatically marked as read upon click or action execution.
* **Segmented Filter Tabs**:
  * Integrated fast filter tabs (`All`, `Unread`, `Alerts`) directly beneath the header with dynamic count badges.
  * Added customized empty-state messaging tailored to each active tab.
* **Smart Deep Linking**:
  * Automatically parses finding IDs (`VULN-xxxx`) from notification text; clicking the notification or its finding chip opens the corresponding finding in the `FindingDrawer` via `onSelectFinding`.
  * Automatically detects GitHub PR numbers and URLs, rendering clickable external badges.
* **Inline "Clear All" Confirmation**:
  * Introduced an in-header two-step confirmation (`Clear all? [Clear] [Cancel]`) for safe wiping without heavy modal dialogs.
* **Relative Timestamps**:
  * Displays friendly relative elapsed times ("Just now", "5m ago", "2h ago", "2d ago") with full locale timestamp available on hover via tooltip.

### 2. Backend Notification Endpoints & Storage
* **Single-Notification Read Marking**:
  * Added `POST /api/notifications/{id}/read` to persist read status for individual notifications in DuckDB/PostgreSQL via `UserNotificationRepository.markAsReadById()`.
* **Complete Notification Purging**:
  * Added `DELETE /api/notifications` to purge all notifications for the authenticated user from storage via `UserNotificationRepository.deleteAllByUserId()`.
* **API Client Expansion**:
  * Updated `auditApi` with `clearNotifications()` and `markNotificationRead(id)`.

### 3. Architecture & Modular Utilities (`notificationUtils.js`)
* **Single Responsibility Principle (SRP)**:
  * Extracted time formatting (`formatRelativeTime`), token extraction (`extractFindingId`, `extractPrInfo`), and tab filtering (`filterNotifications`) into a dedicated utility module.
  * Backed by a 100% green unit test suite (`notificationUtils.test.js`).
