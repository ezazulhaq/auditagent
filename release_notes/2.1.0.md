# AuditAgent v2.1.0 Release Notes

**Release Date:** October 24, 2026

AuditAgent 2.1.0 is a feature and infrastructure release introducing **Manual ZIP Project Upload & Scanning**, containerization enhancements with isolated scanner virtual environments, hardened archive extraction sandboxes, and developer workflow guidelines.

---

## 🚀 New Features & Enhancements

### 1. Manual ZIP Archive Upload & Local Codebase Scanning
Users can now audit local projects and standalone codebases directly by uploading a `.zip` archive without requiring a connected GitHub repository installation.

* **Dual-Mode Scan Configuration Panel**:
  * Added a dedicated mode toggle button adjacent to the collapse chevron in `ScanPanel`, allowing seamless switching between **GitHub Repository Mode** and **Manual Project Upload Mode**.
  * Features a modern drag-and-drop upload zone, interactive file picker, file type and size validation (supporting `.zip` archives up to 50MB), filename/file-size info card, removable file action, and an editable project name input.
  * Preserves scan panel state, showing real-time upload and scan progress with step-by-step diagnostics.

* **Hardened ZIP Extraction Sandbox**:
  * Implemented `ZipArchiveExtractor` to safely extract and inspect archives within an isolated temporary sandbox:
    * **ZipSlip Path Traversal Protection**: Validates every archive entry, ensuring canonical target paths are strictly confined within the designated sandbox root directory.
    * **Magic Byte Header Verification**: Validates the ZIP magic bytes (`0x50, 0x4B`) to reject spoofed or malformed files.
    * **Resource Exhaustion & Zip Bomb Defense**: Enforces strict safety caps—maximum 50MB compressed upload size, 250MB cumulative uncompressed extraction size, and a 10,000 file entry ceiling.
    * **Intelligent Directory Filter**: Automatically filters out heavy build artifacts, dependencies, and metadata folders (`node_modules`, `.git`, `vendor`, `target`, `dist`, `build`, `__pycache__`) during extraction to accelerate Semgrep scanning and reduce memory footprint.
    * **Zero-Trace Disk Hygiene**: All temporary archive payloads and extracted source files are guaranteed to be purged immediately in a `finally` block once the scan completes, ensuring no raw user source code remains on disk.

* **Persistence, Reporting & Export**:
  * Scanned upload results are persisted with key `upload:<uploadId>` in the `reports` table.
  * Added `uploaded_projects` table to track upload metadata, original filenames, project names, and vulnerability counts, securely scoped to the authenticated caller's user session.
  * Integrated on-demand PDF and Markdown report artifact export for manual project scans via `GET /api/reports/upload/export`.
  * Added `UploadedProjectRepository` and service layers for robust data lifecycle management.

* **Remediation Guardrails**:
  * Updated `FindingDrawer` with an informative banner for manual upload findings, clarifying that autonomous GitHub Pull Request creation is disabled for manual uploads (due to the absence of a remote Git repository), while AI remediation guidance, security metrics, and triage details remain fully accessible.

## 🐳 Containerization & Infrastructure Hardening

### 1. Dedicated Python Virtual Environment for Semgrep
* Installed the Semgrep CLI within an isolated Python virtual environment (`/opt/venv`, added to container `PATH`) across all Docker specifications (`Dockerfile`, `Dockerfile.dev`, `Dockerfile.sandbox`).
* Fully complies with Python PEP 668 by avoiding `--break-system-packages` in global system environments, preventing package drift and conflicts with OS libraries.
* Enforces strict least-privilege security boundaries: the virtual environment is owned by `root:root` with read/execute (`755`) permissions, ensuring unprivileged service accounts (`auditagent` / `sandboxuser`, UID 10001) cannot alter, overwrite, or tamper with scanner binaries or dependencies.

### 2. Streamlined Docker Build & Configuration
* Optimized multi-stage Docker builds by consolidating package installation, tooling verification, and user provisioning into unified layers, reducing Docker image size and build times.
* Updated Docker profile initialization to automatically fall back and populate profile configuration from `application-example.yaml` if `application-${PROFILE}.yaml` is not explicitly provided.

## ⚙️ Configuration & API Reference

* **WebFlux Codec Buffer Expansion**:
  * Introduced `WebFluxConfig` setting max in-memory codec buffer limits to 60MB, ensuring reliable handling of large multipart archive uploads without buffer overflow errors.
* **New Backend Endpoints**:
  * `POST /api/scan/upload`: Authenticated endpoint accepting multipart ZIP uploads with Server-Sent Events (SSE) streaming progress (`uploading`, `extracting`, `scanning`).
  * `GET /api/reports/upload?uploadId=...`: Authenticated report retrieval for uploaded projects owned by the user.
  * `GET /api/reports/upload/export?uploadId=...&format=pdf|markdown`: On-demand report export for uploaded project findings.
