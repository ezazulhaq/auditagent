# AuditAgent v2.14.0 Release Notes

**Release Date:** November 20, 2026

AuditAgent 2.14.0 implements **Phase 6: Frontend State Unification & Real-Time Event Architecture**, resolving state fragmentation, cascading re-renders, and aggressive polling overhead across vulnerability remediation workflows. This release introduces a centralized domain reducer (`useRemediationReducer.js`) and dedicated entity normalizer (`remediationNormalizer.js`) to replace 12 fragmented state maps with a single atomic state tree. On the backend, real-time repository event streaming (`GET /api/repositories/{repositoryId}/events?branch={branch}`) delivers reactive push updates for out-of-band GitHub pull request merge/close events, permanently eliminating aggressive client-side polling loops (`setInterval(..., 5000)`) with an adaptive fallback backoff policy.

---

## 🚀 New Features & Enhancements

### 1. Centralized Remediation Domain Reducer & Normalizer
* **Dedicated Entity Normalization (`remediationNormalizer.js`)**:
  * Extracted pure normalization functions (`normalizeRun`, `normalizePublication`, `normalizePreview`, `normalizeGraphSteps`, `createRemediationEntity`, `normalizeHydrateData`) from React components and hooks into an independent, testable module.
  * Ensures uniform handling of LangGraph4j 16-stage timeline events, publication details, preview packages, and run status transitions across both initial hydration and live SSE streaming.
* **Atomic State Tree & Action Reducer (`useRemediationReducer.js`)**:
  * Replaced 12 fragmented `useState` maps (`runs`, `activeVulnId`, `isAnalyzing`, `remediationStatus`, `approvalPreviews`, `graphSteps`, `timelineSteps`, `awaitingApproval`, `publications`, `isPublishing`, `publishErrors`, `selectedPublicationAction`) with a unified normalized state: `{ entities: { [vulnId]: RemediationEntity }, activeVulnId: string | null }`.
  * Implemented 20 explicit action types covering full remediation lifecycle: `HYDRATE_SAVED_RUNS`, `SYNC_FINDINGS`, `SELECT_VULNERABILITY`, `RUN_CHECK_FINISHED`, `REMEDIATION_STARTED`, `REMEDIATION_STREAM_OPEN`, `REMEDIATION_EVENT_RECEIVED`, `APPROVAL_PREVIEW_RECEIVED`, `GRAPH_STEP_RECEIVED`, `REMEDIATION_STREAM_ERROR`, `DECISION_STARTED`, `DECISION_STREAM_OPEN`, `DECISION_EVENT_RECEIVED`, `DECISION_STREAM_ERROR`, `RESET_REMEDIATION_STATE`, `SET_SELECTED_PUBLICATION_ACTION`, `PR_LIFECYCLE_EVENT`, `DISMISS_PUBLISH_ERROR`, `OPTIMISTIC_MERGE_CONFIRMED`, `RUN_DISCARDED`.
  * Provided memoized selectors (`selectActiveEntity`, `selectAwaitingApproval`, `selectIsAnalyzing`, `selectGraphSteps`, `selectRunsMap`, `selectIsAnalyzingMap`, `selectHasOpenPr`) eliminating cascading component re-renders during high-velocity 16-stage LangGraph4j agent progress streams.
* **Refactored Controller (`useRemediationController.js`)**:
  * Unified controller state management under `useRemediationReducer`.
  * Preserved full backwards-compatible return contract for all UI consumers (`FindingDrawer.jsx`, `RemediationDecisionBar.jsx`, `WorkspaceTabs.jsx`, etc.) while delegating state transitions cleanly to reducer dispatches.

### 2. Real-Time Repository SSE Event Streaming & Polling Elimination
* **Backend Repository SSE Channel (`AuditController.java`, `EventBroadcastService.java`)**:
  * Implemented `GET /api/repositories/{repositoryId}/events?branch={branch}` providing long-lived Server-Sent Events (`text/event-stream`) for repository-scoped events.
  * Extended `EventBroadcastService` with repository sink registry (`ConcurrentMap<Long, List<Sinks.Many<ServerSentEvent<Map<String, Object>>>>>`), periodic keepalive heartbeats (15s pulses), and auto-cleanup on client disconnect or cancellation.
  * Cross-node clustering support: RabbitMQ fanout exchange `auditagent.events` routes repository broadcast events seamlessly to all active web pod subscribers.
* **Automated Webhook PR Lifecycle Broadcasting (`PullRequestLifecycleService.java`)**:
  * On GitHub `pull_request` webhook delivery (`action: closed`, `merged: true`), `PullRequestLifecycleService` now broadcasts a typed `pr_lifecycle` event carrying `repositoryId`, `branch`, `pullRequestNumber`, `merged: true`, and associated vulnerability IDs.
* **Reactive Frontend SSE Client & Polling Removal (`auditApi.js`, `useRemediationController.js`)**:
  * Implemented `subscribeRepositoryEvents(repositoryId, branch, onEvent, signal)` in `auditApi.js`.
  * Completely eliminated the legacy 5-second `setInterval` polling loop in `useRemediationController.js`.
  * Active PR states (`PR_OPEN`) are updated reactively via SSE push stream.
  * Integrated an adaptive fallback backoff mechanism (30s, 60s, 120s up to 300s ceiling) that only engages if SSE disconnects or encounters repeated transport failures.
