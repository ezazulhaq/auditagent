# AuditAgent v2.3.0 Release Notes

**Release Date:** October 31, 2026

AuditAgent 2.3.0 introduces a Bring-Your-Own-Key (BYOK) LLM architecture, empowering users to supply their own API keys and select their preferred models via OpenRouter (the default provider) or any OpenAI-compatible provider. This release adds a mandatory onboarding modal upon login, a user profile settings modal for ongoing credential management, live connection testing before saving, AES-GCM encrypted persistence at rest, and dynamic user-scoped client caching.

---

## 🚀 New Features & Enhancements

### 1. Bring-Your-Own-Key (BYOK) Architecture (`UserLlmConfigService`, `UserLlmClientFactory`)
* **OpenRouter as Default Provider**:
  * Default configuration routes requests through OpenRouter with curated frontier model presets (`anthropic/claude-3.5-sonnet`, `openai/gpt-4o`, `google/gemini-2.5-flash`, `glm-5.3-flash`, `deepseek-chat`) and arbitrary custom model IDs.
  * Injects required OpenRouter routing headers (`HTTP-Referer`, `X-Title`) into model invocations.
* **OpenAI-Compatible Custom Endpoints**:
  * Allows configuring custom API base URLs (e.g., self-hosted proxies, LiteLLM, vLLM, or direct OpenAI endpoints).
* **Dynamic User-Scoped Client Caching**:
  * `UserLlmClientFactory` dynamically provisions and caches `ChatModel` (Spring AI) and `OpenAiChatModel` (LangChain4j) instances per authenticated user.
  * Caches instances using a concurrent cache keyed by `userId:hash(apiKey,provider,model,baseUrl)`, with automatic eviction upon configuration updates.
* **Supervisor Model Customization**:
  * Optional advanced setting allowing users to specify a separate supervisor model for multi-agent triage and routing in LangGraph4j workflows.

### 2. Mandatory Onboarding & Profile Settings UI (`LlmOnboardingModal`, `UserProfileModal`, `LlmConfigForm`)
* **Mandatory Onboarding Gate**:
  * When `auditagent.llm.user-keys-required` is active (default: `true`), newly authenticated users without saved credentials are presented with an unclosable onboarding dialog before accessing AI features.
* **Profile & LLM Settings Modal**:
  * Accessible at any time from the user avatar dropdown in `AppHeader` ("Profile & LLM Keys").
  * Displays authenticated GitHub identity, active provider, model selections, and a securely masked API key (`sk-or-••••••••3a8f`).
  * Allows users to update keys, switch providers, change models, and re-test connectivity.
* **Live Connection Testing**:
  * Integrated **Test Connection** button sends an ephemeral ping prompt to verify API credentials and model availability before persisting settings.
  * Renders clear success badges or detailed diagnostic error messages directly in the form.

### 3. Enterprise Security & Encryption (`TokenCipher`, `user_llm_configs`)
* **AES-GCM Encryption at Rest**:
  * User API keys are encrypted at rest using AES-GCM with a 12-byte random IV via `TokenCipher`. Plaintext keys are never stored in database columns or output in logs.
* **Key Masking & API Protection**:
  * `GET /api/user/llm-config` returns only masked keys. When updating configuration, users can choose to retain their existing encrypted key without re-entering it.
  * All modification endpoints enforce strict user session authentication and CSRF token validation (`X-CSRF-Token`).
* **Subprocess Sanitization**:
  * User credentials are never passed to scanner (Semgrep) or compiler (Maven, Gradle) subprocesses executed by `ManagedProcessEnvironment`.

### 4. Fast-Fail Error Handling (`UserLlmConfigurationException`, `ApiExceptionHandler`)
* Attempts to initiate chat or multi-agent remediation without configured credentials fail fast with HTTP 422 Unprocessable Entity (`LLM_KEY_REQUIRED`).
* Remediation SSE streams emit structured `error` events with `requiresLlmConfig: true`, triggering immediate notification banners with one-click access to settings.
