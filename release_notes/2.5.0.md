# AuditAgent v2.5.0 Release Notes

**Release Date:** November 10, 2026

AuditAgent 2.5.0 introduces the **Scalability & Messaging Architecture**, transitioning heavy background workloads (vulnerability scanning and autonomous multi-agent remediation) from local in-memory virtual thread dispatching into an enterprise asynchronous messaging pattern backed by **RabbitMQ** task queues, **Supabase PostgreSQL** transactional and lexical persistence, **Supabase Storage** for report/artifact archiving, and Realtime SSE event relaying. This release also introduces robust consumer dead-letter queue routing (`AmqpRejectAndDontRequeueException`), lifecycle re-analysis for findings in `AWAITING_APPROVAL` status, and frontend error state hydration with retry actions in the finding details drawer.

---

## 🚀 New Features & Enhancements

### 1. RabbitMQ Task Queue & Asynchronous Workers
* **Dedicated Task Queues**: Configured `auditagent.scan.queue` and `auditagent.remediation.queue` bound to direct exchange `auditagent.direct.exchange`, with dead-letter queue routing to `auditagent.dlq`.
* **Priority Task Producer**: Added `TaskProducerService` with priority-aware queuing (`enqueueScanTask`, `enqueueRemediationTask`) allowing urgent security audits to supersede routine batch scans.
* **Asynchronous Consumers**: Added `ScanTaskConsumer` and `RemediationTaskConsumer` processing queued workloads with bounded concurrency and transactional execution.
* **Dead-Letter Routing & Poison Message Protection**: Hardened worker consumers to catch unrecoverable exceptions and throw `AmqpRejectAndDontRequeueException`, immediately routing poisoned tasks to `auditagent.dlq` without triggering infinite redelivery loops.

### 2. Persistence Consolidation (Supabase PostgreSQL & Storage)
* **DuckDB Retirement**: Replaced local file-based DuckDB with PostgreSQL transactional persistence and full-text search (`tsvector` / BM25-equivalent) via `PostgresKnowledgeBaseService`.
* **Database Checkpoint Saver**: Implemented durable LangGraph4j state checkpointing in PostgreSQL via `DatabaseCheckpointSaver`, eliminating local checkpoint file locking issues.
* **Supabase Storage Integration**: Implemented `SupabaseStorageService` for uploading, archiving, and retrieving scan reports, HTML summaries, and remediation evidence.
* **Job Event Audit Log**: Created `job_event_log` table and `JobEventLogRepository` to track lifecycle transitions for background jobs and drive the SSE event relay.

### 3. Workflow Lifecycle Robustness & Identity Preservation
* **Lifecycle Re-Analysis**: Updated `RemediationDataService` to query non-terminal statuses (`AWAITING_APPROVAL`, `CONFLICTED`, `PUBLISHING`, `PUBLISH_FAILED`) and updated `CloneWorkspaceNode` to allow re-analysis by safely discarding stale workspaces and resetting findings to `DETECTED`.
* **Authentic Identity Preservation**: Worker tasks reconstruct authentic GitHub identities using `UserDataService.findUserById`, ensuring remote branch commits and PRs are properly attributed.

### 4. Frontend State & UI Error Recovery
* **Error State Hydration**: Enhanced `useRemediationController` to properly hydrate `FAILED` status and trigger `refreshReport` upon encountering task failures or SSE errors, preventing UI drawers from spinning indefinitely.
* **Finding Drawer Retry Action**: Added explicit retry action buttons in `FindingDrawer` for `PATCH_FAILED` findings and failed remediation runs.
* **Defensive SSE Parsing**: Updated `sse.js` to strip redundant `data:` prefixes defensively, ensuring reliable event deserialization across proxies and relays.

## ⚙️ Configuration Reference

```yaml
spring:
  rabbitmq:
    host: ${RABBITMQ_HOST:localhost}
    port: ${RABBITMQ_PORT:5672}
    username: ${RABBITMQ_USERNAME:auditagent}
    password: ${RABBITMQ_PASSWORD:auditagent_password}
    virtual-host: ${RABBITMQ_VHOST:/}
    listener:
      simple:
        acknowledge-mode: auto
        concurrency: 2
        max-concurrency: 5

auditagent:
  storage:
    supabase:
      url: ${SUPABASE_URL:}
      service-key: ${SUPABASE_SERVICE_ROLE_KEY:}
      bucket: ${SUPABASE_STORAGE_BUCKET:audit-reports}
```
