# AuditAgent v2.14.3 Release Notes

**Release Date:** November 22, 2026

AuditAgent 2.14.3 introduces durable notification persistence directly from background workers (`RemediationWorkflowService` and `ScanOrchestratorService`) for terminal failures and milestone outcomes, paired with server-side time-window deduplication in `UserDataService` to ensure notifications are never lost when browser tabs are closed or disconnected.

---

## 🚀 Enhancements & Architecture Refactoring

### 1. Background Worker Durable Notifications
* **Direct Worker Persistence**:
  * Updated `RemediationWorkflowService` to record notifications directly to `user_notifications` via `DatabaseService.saveNotification(...)` upon terminal remediation task failure (such as `STALE_BASE`, compilation failures, or runtime exceptions) with the user-friendly classified error message.
  * Added milestone `success` notifications on autonomous pull request creation (`publish` node).
  * Added durable notifications to `analyzeDirect` and batch remediation workflows.
  * Updated `ScanOrchestratorService` to directly persist `success` notifications upon scan completion and `error` notifications upon scan failures (such as `SCAN_TIMEOUT` or execution exceptions).
* **Guaranteed Delivery Across Browser Lifecycles**:
  * Notifications are stored directly in PostgreSQL/database by asynchronous workers, eliminating the dependency on active SSE subscriptions or open browser tabs.

### 2. Notification Deduplication Window
* **Time-Window Deduplication in `UserDataService`**:
  * Implemented 60-second time-window deduplication across `userId`, `type`, and `message` in `UserDataService.saveNotification(...)`.
  * Added `existsByUserIdAndTypeAndMessageAndCreatedAtAfter` query to `UserNotificationRepository`.
  * Prevents duplicate notification records when both the asynchronous background worker and an active frontend SSE client attempt to save the same event.
