# AuditAgent v2.7.0 Release Notes

**Release Date:** November 13, 2026

AuditAgent 2.7.0 delivers **Phase 1: Concurrency and Real-Time Stability**, addressing key operational bottlenecks identified during the scalability architecture review. This release establishes a distributed cross-pod event pipeline via RabbitMQ, eliminates Java 21 carrier-thread pinning from legacy `synchronized` locks, aligns repository static analysis with the asynchronous task queue, introduces bounded concurrency and HTTP 429 exponential backoff for finding triage, and isolates LangGraph4j sub-agent checkpoints.

---

## 🚀 New Features & Enhancements

### 1. RabbitMQ Cross-Pod Event Pipeline (`auditagent.events`)
* **Multi-Pod Event Broadcasting**:
  * Declared a durable `auditagent.events` Fanout exchange (`RabbitMqConfig.java`) and an ephemeral, exclusive `AnonymousQueue` (`eventIngressQueue`) for each web ingress pod.
  * Updated `EventBroadcastService` to serialize and broadcast enriched event payloads (`jobId`, `runId`, `type`) over `auditagent.events` while persisting to PostgreSQL `job_event_log`.
  * Added `EventIngressListener` on web pods to dispatch incoming events in $O(1)$ directly to local client SSE Flux sinks matching `jobId`, dropping unrelated events without overhead.
  * Maintained full local in-memory sink fallback when running in standalone mode or without RabbitMQ.

### 2. Carrier-Thread-Safe Striped ReentrantLock Concurrency
* **GitHub OAuth Token Refresh**:
  * Replaced method-level `synchronized String accessToken(String userId)` in `GitHubAuthService` with an identifier-striped `ReentrantLock` keyed by `userId`.
  * Allows Java 21 virtual threads to unmount from underlying OS carrier threads during blocking HTTP code exchanges, preventing User A from blocking User B.
  * Double-checked expiry verification inside the lock prevents duplicate refresh requests for the same user.
* **Workspace Preparation**:
  * Replaced `synchronized (database)` in `CloneWorkspaceNode` with an identifier-striped `ReentrantLock` keyed by `repositoryId:branch:fingerprint`.
  * Serializes execution only for overlapping runs of the identical finding, enabling independent findings and repositories to clone and prepare concurrently without global lock contention.

### 3. Scan Queue Alignment (`enqueueAndStreamScan`)
* **Unified Asynchronous Scan Processing**:
  * Added `enqueueAndStreamScan` in `ScanOrchestratorService` and updated `POST /api/scan` in `AuditController`.
  * Verifies commit snapshot cache hits instantly, or dispatches a `ScanTaskPayload` to RabbitMQ queue `auditagent.scan.queue` (prefetch: 2) with priority from `auditagent.scanner.queue-priority` (default: 5).
  * Streams real-time progress and completion events transparently back to the client via `EventBroadcastService`.

### 4. Bounded Concurrency & Exponential Backoff in Finding Triage
* **Semaphore Throttling & HTTP 429 Resilience**:
  * Added `auditagent.jev.triage.concurrency` (default: 8, range: 1–32) to `JevProperties`, guarded by a `Semaphore` in `FindingTriageService`.
  * Implemented exponential backoff retry on HTTP 429 Rate Limits (`500ms`, `1500ms`, `3500ms` + jitter).
  * Findings that exhaust retries are gracefully retained with default metadata and triage classification marked as `UNVERIFIED` rather than failing the scan.

### 5. Multi-Tenant LangGraph4j Checkpoint Isolation
* **Namespaced Sub-Agent Checkpoints**:
  * Updated `MultiAgentRemediationGraph` to pass `String.format("%s:%s:%s", threadId, runId, stage.name())` as `threadId` in `RunnableConfig`.
  * Checkpoints stored in PostgreSQL `graph_checkpoints` are strictly namespaced by thread, run, and sub-agent stage, preventing state overwrites across concurrent runs.
