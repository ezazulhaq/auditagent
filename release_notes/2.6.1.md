# AuditAgent v2.6.1 Release Notes

**Release Date:** November 12, 2026

AuditAgent 2.6.1 delivers key reliability and user experience enhancements to the autonomous remediation and review workflow. This release resolves finding review state thrashing during background polling, introduces automatic fallback run association for findings awaiting approval across conversation resets and page reloads, and ensures users always have an actionable recovery path when previous remediation runs are no longer recoverable.

---

## 🚀 Enhancements & Defect Resolutions

### 1. Fallback Active Run Association (`GET /api/runs/vulnerability/{vulnId}`)
* **Cross-Thread & Page-Reload Run Recovery**:
  * Added `GET /api/runs/vulnerability/{vulnId}` endpoint to `RunPublicationController` to look up active or recoverable runs (`ACTIVE`, `INTERRUPTED`, `AWAITING_APPROVAL`, `PUBLISHING`, `PUBLISH_FAILED`, `PR_OPEN`) by vulnerability ID.
  * Added `findActiveRunForVulnerability` to `RemediationWorkflowService`, `DatabaseService`, and `RemediationDataService` with repository access validation.
  * Added `findByVulnerabilityIdAndStatusInOrderByUpdatedAtDesc` to `AgentRunRepository`.
* **Client-Side Fallback Retrieval**:
  * Updated `useRemediationController` to automatically query `GET /api/runs/vulnerability/{vulnId}` whenever an active or `AWAITING_APPROVAL` finding lacks a local in-memory run (e.g. after conversation reload or cross-thread navigation).
  * Added fallback run resolution in `loadApprovalPreview(vulnId)` if the run is missing when the user triggers diff review.

### 2. Finding Drawer & Decision Bar Reliability
* **Non-Blocking Review Loading & Run Verification Feedback**:
  * Introduced `isLoadingRun` tracking to `useRemediationController` and propagated it via `AuditContext` and `ModalManager` to `FindingDrawer` and `RemediationDecisionBar`.
  * The review button displays `<LoaderCircle className="animate-spin" /> Checking remediation run...` while querying the backend and disables duplicate interaction.
* **Orphaned Run Recovery & Re-Analysis Action**:
  * If a finding's prior run was discarded or expired from disk, `RemediationDecisionBar` renders clear guidance alongside a **"Re-analyze in isolated workspace"** button rather than a dead-end static status banner.
* **Diff Preview Retention Across Polling**:
  * Updated `hydrate()` in `useRemediationController` to preserve in-memory verified diff previews when `runId` matches the active run, preventing button state thrashing and eliminating the regression where **"Approve & create PR"** reverted back to **"Review verified diff"** every 5 seconds.
